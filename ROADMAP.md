# 📱 Project Roadmap & Features

Back to the [README](README.md).

### Phase 1: Foundation & Core Logic I
- [x] **Dynamic Month Navigation:** Sliding window navigation moving back and forth within a fixed range of 24 months.
- [x] **Single Entry Management:** Ability to add and track one-time expenses.
- [x] **Recurrence Engine:** Implement the 3 recurrence types (OneTime, Installments, Recurrent) with automated distribution.
- [x] **Separation between income and outcome entries:** Differentiate visually and functionally between incomes and expenses.
- [x] **Edit modal:** Opens when the user taps an entry. Edits Description, Amount, and Category on the template. EntryType and Recurrence are intentionally locked — see architectural constraint below.
- [x] **Delete entry:** Long-press (1s) an entry to slide in an actions menu from the right (currently a delete button; room for more actions). Tapping anywhere else slides it back out. OneTime entries are removed entirely; Recurrent/Installments entries offer three scopes: *this month only* (cancelled `FinancialMonthlyEntry`), *this and future months* (sets `EndDate` on the template), or *all months* (removes the template and its monthly records).
- [x] **Category Management:** Dynamic category CRUD (name, emoji icon, color) on a "Categorias" page reached via the hamburger menu. Entries show their category chip in the monthly list. Deleting a category keeps its entries and leaves them uncategorized. The former hardcoded categories are seeded on first run and existing entries are re-linked by name.
- [x] **Income and outcome UI improvements:** Change the UI of the income and outcome list so that it becomes easier to identify that they are two different sessions. In addition, it should be clear that the sessions can be expanded/collapsed.
- [x] **UX improvements:** Description field auto-focused on popup open; income/outcome selection is a swipe/tap pill toggle defaulting to Outcome; the amount field only appears after the recurrence is chosen and is labelled accordingly ("Valor total", "Valor mensal" or "Valor de cada parcela", with a live installment total).
- [x] **Improve total amount for Installment entries:** Show the total amount of the installment in the list, not just the current month amount.
- [x] **E2E tests:** Appium 2 + UiAutomator2 suite in `FinanceApp.UITests` that drives the real Android app on an emulator. It uses page objects located by `AutomationId`, asserts on the app's on-device SQLite database, and has a GitHub Actions workflow that runs on every merge to `master`. Starts with the add-entry flow; see [FinanceApp.UITests/README.md](FinanceApp.UITests/README.md) to run it.
- [x] **Improve CI automation:** Claude opens the pull request itself at the end of each task with the GitHub CLI (`gh`), using the PR template in `.github/pull_request_template.md` (summary, test results, roadmap item), then checks its CI. The E2E workflow now runs on every merge to `master`.
- [x] **Status control:** The long-press actions menu gains a "Pagar" (outcomes) / "Receber" (incomes) action that marks the entry as paid for that month only, and a "Pendente" action to undo it. Paid entries show a filled check icon and a "Pago"/"Recebido" label; pending entries show an empty ring. The status is lazily persisted as a `FinancialMonthlyEntry` for that month, so other months of a recurrent or installment entry stay pending.
- [x] **Separate income and outcome categories:** Each category now has a type (Despesa/Receita), chosen with a toggle in the category popup. The "Categorias" page lists them in two groups, and the entry popup only offers categories matching the selected entry type. Existing categories are migrated as outcome categories, and "Salário" and "Investimentos" are seeded as income categories.
- [x] **Improve month navigation:** Tapping the month title (marked with a ▾) opens a month/year picker: a year switcher and a 3×4 month grid limited to the ±24-month range, plus a "Mês atual" shortcut. When away from the current month, a floating "Mês atual" pill appears at the bottom of the screen, with an arrow pointing toward the current month, to jump back in one tap.

### Phase 2: Foundation & Core Logic II
- [x] **Add currency mask to the amount fields:** Every amount in the app (entry rows, section totals, month summary, installment totals) is shown as Brazilian currency, e.g. "R$ 1.000,00" (negative balances as "-R$ 1.000,00"). The amount field in the entry popup is masked the same way while typing: digits fill in from the cents, like a banking app (typing 1, 5, 0, 0 gives "R$ 15,00").
- [x] **Improve the 'recorrente' option:** The recurrence picker now reads "Todo mês (recorrente)" so its meaning is clear to every user.
- [x] **Improve the month picker button:** The month title is now a large tappable pill with a filled ▾ badge that opens the month/year picker, flanked by 48dp "‹" / "›" buttons that step one month (disabled at the ends of the ±24-month range). Below it, a hint ("Toque no mês para escolher ou deslize para os lados") teaches both the picker and swiping; it is dismissed for good the first time the user changes month.
- [x] **Entry paid checks are red:** The paid check icon and the "Pago"/"Recebido" label now use the same green for incomes and outcomes, instead of the outcome red that could read as an error.
- [x] **Add paid/pending amount to the month summary:** The month summary is a three-page pager: swipe it sideways (or tap the dots below it) to go from Receitas/Despesas/Balanço to Pago/A pagar and then to Recebido/A receber. The selected page stays the same when changing month. Partial payments count towards both sides.
- [x] **Partial payment and estimated amount:** The long-press actions menu gains "Pagar parcial" ("Receber parcial" for incomes), which opens a popup to add a payment to what was already paid that month (e.g. today's supermarket bill), showing the amount so far and the new total. The edit popup also has a "Valor já pago neste mês" field to correct the month's total. Payments apply only to that month and are stored on its `FinancialMonthlyEntry`. A partially paid entry shows an orange ring, with the amount paid so far and a progress bar under its price. Payments never mark it as paid by themselves (only "Pagar" does, since an estimated expense can keep growing until the month ends), paying more raises that month's amount (e.g. a bill that came higher than estimated), and clearing it reverts to pending. "Pagar"/"Pendente" settle or reset the whole amount. Entries can also be flagged as "Valor estimado" (a switch in the popup) for amounts that vary every month, like energy bills; they show a "±" badge next to the amount.
- [x] **Partial payment records:** Each payment added with "Pagar parcial"/"Receber parcial" is saved as its own record (`FinancialPayment`, linked to the month's `FinancialMonthlyEntry`) with the amount, a date (defaults to today, kept within the month being paid) and an optional description. The "Pagar parcial" popup is only for adding payments; the month's payments are listed in the entry details (tap the entry), under "Valor já pago neste mês", as "Pagamentos neste mês"/"Recebimentos neste mês". Each one can be removed with its ✕, which subtracts it from the amount paid once the entry is saved ("Cancelar" keeps it). "Pagar parcial" stays available once the entry is paid, so a bill that came higher can still be recorded. "Pagar" settles the month, keeping the total when more than planned was paid, and keeps the history; reverting it to pending (or clearing "Valor já pago neste mês") resets the month and removes its payments.
- [x] **Partial payment underestimated:** When a month's payments go beyond the planned amount (the template amount or that month's override), the row's price shows what was paid and, under it, a ▲ (red for outcomes, green for incomes) with the planned amount struck through, plus a full progress bar whose tip marks the excess. This applies to that month only, and the entry stays partially paid until "Pagar". Everything about the amount sits on the right, under the price, so the price stays the main element. The partial payment popup warns before saving when the new total would exceed the planned amount, and its progress line compares the total against the planned amount.
- [x] **Flag entries with partial payment:** Entries have a "Pagamento parcial" switch ("Recebimento parcial" for incomes) in the entry popup, off by default, for entries paid little by little like the supermarket. Only flagged entries offer "Pagar parcial"/"Receber parcial" in the long-press actions menu and the "Valor já pago neste mês" field in the entry details. Turning the flag off keeps what was already paid, and the month's payments stay listed in the details so they can still be removed. Existing entries that already had partial payments are migrated with the flag on.
- [x] **Due date:** Entries have an optional due day ("Vencimento" picker in the entry popup: "Sem vencimento" or "Dia 1" to "Dia 31"), stored on the template as `DueDay`, so recurrent and installment entries fall due on that day every month (days past the end of a month fall on its last day, e.g. 31 is February 28th). The row shows "Vence 05/11" under the category, and "Vence hoje" in bold red when the entry is due today and not yet paid/received. The due day can be changed or cleared when editing.
- [x] **Add/edit entry modal:** Adding or editing an entry now opens a full-screen page instead of a popup, so the growing form has room. The description field is focused on open, with the keyboard up. Its header has a "←" back button that stays on screen however far the form is scrolled (the Android back button works too); both leave without saving, like "Cancelar". "Cancelar" and "Salvar" sit at the end of the form. After saving, the list is refreshed and the app returns to the month the page was opened from.
- [x] **Alterating colors on the entry lists:** Every other row of the income and outcome lists has a light background in its section's color (pale red for outcomes, pale green for incomes), lighter than the section headers, so each row is easier to follow. The alternation restarts in each section and follows the list order, so it stays consistent after adding or deleting entries.
- [x] **Payment source engine:** A "Contas e cartões" page in the hamburger menu manages payment sources (`PaymentSource`): bank accounts, credit cards and meal vouchers, listed in three groups ("Contas bancárias", "Cartões de crédito", "Vales"). Tapping "+" or a row opens a popup to set the name, the type and the balance, labelled "Saldo" for accounts and vouchers and "Limite" for credit cards. The entry page has a "Pago com" picker ("Recebido em" for incomes) that links the entry to a source, and the entry row shows the source (with its type icon) under the category. Renaming a source updates the rows. Deleting it keeps its entries and unlinks them. The bottom of the hamburger menu shows a "Saldo atual" list with each source's balance (or limit), and tapping one opens it to update the balance. For now the balance is only what the user types: payments don't change it yet.
- [x] **App lock with PIN and biometrics:** A "Segurança" page in the hamburger menu turns on a 4-digit PIN ("Bloquear com PIN"), typed twice to confirm, on a full-screen keypad. Once it's on, the PIN can be changed ("Alterar PIN") or turned off, both asking for the current PIN first, and "Desbloquear com biometria" lets the device's fingerprint or face unlock the app (it asks for it once to turn it on, and explains when the device has none enrolled). The lock screen shows up when the app starts and when it comes back after more than 1 minute in the background; it can't be dismissed (Back leaves the app), and a wrong PIN shows "PIN incorreto". The PIN is stored only as a salted hash in the device's secure storage. There is no account yet, so the page warns that the data stays only on this device and that a forgotten PIN can't be recovered, and "Esqueci o PIN" on the lock screen explains that the only way out is clearing the app's data. Login/account moved to Phase 3, with the backend.
- [x] **Add a setup page for new users:** The first time the app opens, a full-screen wizard ("Passo 1 de 5", with "Pular" on every step) builds the user's first month. It covers: name and an optional photo; accounts, cards and vouchers ("Onde fica o seu dinheiro?"); salary, pay day and "Recebido em"; and house expenses (rent or financing, condo fee, energy, water, internet, phone, supermarket) with a monthly amount, a due day and a shared "Pago com". Energy and water are flagged "Valor estimado"; supermarket is estimated, paid little by little and has no due day. The first bank account added becomes where the salary lands and the expenses are paid. The last step lists the entries to create with the monthly income, expenses and balance, and explains each recurrence type, estimated amounts and partial payments. "Começar" creates them as recurrent entries from the current month, in "Salário", "Moradia" or "Mercado". The name and photo show at the top of the hamburger menu ("Olá, Ana!"). "Refazer configuração inicial" in the menu opens the wizard again to add more without touching existing data. People who already had data never see it.
